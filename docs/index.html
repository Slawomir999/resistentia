Alert Log Diagnosis

Most alerting is judged on whether it fires. This judges whether it stops. Drop in a log — one row per sample, a column saying whether an alert was active, and where you have it a column saying whether anything was actually wrong — and it returns one of five regimes.     Thresholds

    Engineering defaults, not findings. A domain where sustained response is normal — continuous process control, life support — should raise the termination threshold and say so in whatever it reports.

    Log format

    One row per sample at a constant interval. Column names are matched loosely: firing also accepts alert, alarm, active, state, response; truth also accepts incident, warranted, actual, fault, ground_truth. Values may be 1/0, true/false, yes/no, alert/ok. The truth column is optional — without it, coverage and false dwell cannot be computed, but non-termination and oscillation still can, which is most of what goes wrong.

    An episode still open at the end of the log counts as terminated when the truth column is true at the final sample. A response that stays active because its cause is still active has not failed to terminate; only one that outlives its cause has. Specified in RTS-1 §5.
